Safety and operational limits

Understand what saving, plugins and local client access protect, and what they do not.

Keep backups or version control. This release has no automatic crash recovery, autosave journal or backup generation. A process crash, forced quit or out-of-memory termination can lose unsaved work.

Save path

The backend writes a temporary file in the destination directory, flushes and fsyncs its contents, checks the destination again for an external change, and atomically renames the temporary file onto the destination. Existing permission bits are copied when possible. Directory fsync and metadata preservation are best-effort, not a guarantee that every filesystem or power-loss scenario is durable.

The editor detects ordinary stale-buffer cases using saved file metadata and refuses an overwrite unless explicitly forced. This is not a cryptographic content check or a lock against every time-of-check/time-of-use race. Another writer can still race the final check/rename. Never assume simultaneous writes from unrelated editors merge automatically.

Atomic replacement changes file identity. Hard-link relationships, ACLs and extended attributes are not preserved. Existing symlink targets are resolved so the symlink itself is not simply replaced, but adversarial path changes are outside the guarantees. Special files, remote files and arbitrary binary data are not supported editing targets.

Text and resource limits

Files must be valid UTF-8 without NUL. BOM and uniform CRLF are preserved; arbitrary legacy encodings and mixed-newline fidelity are not promised. Editing uses code points rather than grapheme clusters. Display width and rendering depend on terminal/X11 fonts and locale; complex emoji and combining sequences may not align like a modern shaping engine.

There is no hard cap on complete file size apart from allocation/system limits, but input is read into memory. The additions store and undo records can grow without a compaction or history-budget policy. Out-of-memory allocation terminates the process. Highlighting stops above 16 MiB per buffer or 256 KiB per displayed line; protocol text transfers have smaller per-request limits.

Trusted Python and formatters

Configuration is ordinary trusted Python, not a sandbox. It can read and write files, launch programs or consume all process resources. A same-user client can invoke configured commands. Do not load unknown configurations or expose the Unix socket beyond a private directory. Never bridge it to the network without designing separate authentication and authorization.

The bundled formatter avoids shell interpolation, uses bounded input/output validation and timeout checks, and changes the buffer only after success. These measures protect editing state from ordinary failures; they do not make a malicious executable safe. It can alter files or resources under the user's account independently of the editor's temporary file.

Shutdown and recovery

Normal quit prompts when a buffer is modified. kill-emacs, a forced protocol quit and external process termination can bypass this. Detaching a client preserves a persistent backend but not a backend that is itself terminated. A stale Unix socket path is intentionally not replaced; confirm the previous process is gone before manually removing it.

The terminal frontend restores termios and its alternate screen on its tested normal/SIGTERM paths. SIGKILL and abrupt system failure cannot run cleanup. If a terminal is left in a broken state, use a new terminal or the shell's stty sane and reset commands as appropriate. This is recovery for display state, not for unsaved text.
