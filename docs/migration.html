Porting the supplied .emacs

The supplied configuration is represented as Python editing policies, with each meaningful difference recorded.

Load examples/dotemacs.py with --config, or import cpymacs_plugins.dotemacs and call install(api) from your own config. The original file is input to this port, not executable code in cpymacs.

Four-space default versus two-space profile

# Stock behavior: TAB inserts four spaces in a new plain buffer.
./build/cpymacs --nox

# The port preserves the supplied web-specific two-space exception.
./build/cpymacs --nox --config examples/dotemacs.py page.html

# Python/Cython remain four-space modes under the same profile.
./build/cpymacs --nox --config examples/dotemacs.py example.py

A single global four-space claim would misrepresent the supplied .emacs, whose web hook explicitly requests two spaces. Conversely, applying two spaces globally would violate the requested default. The optional, mode-local profile keeps the two policies separate.

What is not equivalent

This port does not execute Lisp, download Emacs packages, reproduce their full syntax tables, preserve every marker during formatting or provide their complete indentation engines. It preserves the specified filename routing, key choices, whitespace behavior, optional formatter sequence and failure protection within the documented native editor subset.
