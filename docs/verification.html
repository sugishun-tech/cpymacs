Verification record

Executed tests and explicitly unverified areas for this source release.

Recorded environment

GNU/Linux x86-64, Debian toolchain, GCC 14.2.0, CPython 3.13.5, json-c 0.18 and Xlib with Xvfb. Verification took place in the supplied local container, not on the user's desktop. Automated GUI events are real X11 events under a virtual display, not a screenshot mock-up.

The integration suite contains subtests in addition to its 43 named tests, including requested filename-routing cases. Do not add those subtests to the headline count to inflate it. CTest exposes a smaller number of top-level suite entries; that number is not the number of unittest cases.

Failure-path coverage

Tests check stale-file overwrite refusal, explicit forced saves, preservation of file modes and symlinks, CRLF/BOM handling, invalid UTF-8/NUL files, read-only edits, mid-code-point positions, plugin exceptions, before-save cancellation, long-line column checkpoints and socket permissions. Formatter tests check exact flags, order, same-directory temporary files, missing executables, nonzero exit, timeout, invalid output, temporary-file cleanup and unchanged buffers on failure.

The GUI test exercises native key events, saving, selection, an 80,000-byte incremental clipboard transfer, external clipboard yanking, resize, clicking, detaching and reconnecting a new GUI to the same server. The PTY test includes non-ASCII pasted text and checks terminal attributes after exit. This is more than a successful compile, but not exhaustive interactive testing.

Run the checks

ctest --test-dir build --output-on-failure
/usr/bin/python3 tests/check_docs.py

cmake -S . -B build-asan -G Ninja     -DCMAKE_BUILD_TYPE=Debug -DCPYMACS_SANITIZERS=ON     -DCPYMACS_LTO=OFF -DPython3_EXECUTABLE=/usr/bin/python3
cmake --build build-asan -j
ASAN_OPTIONS=detect_leaks=0 ctest --test-dir build-asan --output-on-failure
ASAN_OPTIONS=detect_leaks=1 ./build-asan/test_text

Full-process leak checking is disabled in the integrated sanitizer run because embedded CPython retains process-global allocations. The native text-store test is checked separately with leak detection enabled. ASan/UBSan passing is evidence about executed paths, not proof of memory safety.

Build variants and installation

The Release build with the GUI enabled passed all three CTest suites in 32.85 seconds. The Release build with CPYMACS_GUI=OFF passed all three suites in 29.62 seconds; its GUI unittest was explicitly skipped while both PTY tests ran. The headless binary has no X11 dependency, and the separate GUI binary has no Python or editing-core dependency.

Installation was verified from an unrelated working directory with the original source Python directory temporarily unavailable. The installed profile loaded successfully, activated Python and web modes, and reproduced two-space web TAB behavior even with a numeric prefix. That final profile regression was also rerun under ASan/UBSan.

Not verified or not provided

No differential command run against an installed GNU Emacs release was performed. No controlled speed comparison with simplepypad or GNU Emacs was performed. Real isort/autopep8 versions, Japanese IME preedit/commit with IBus or Fcitx, native Wayland, Windows/macOS, all fonts/terminal emulators, concurrent adversarial clients, power-loss recovery and exhaustive filesystem fault injection were not verified.

GitHub Actions workflows are included, but a remote CI or Pages deployment was not executed from this local source delivery. The source's compatibility and safety limitations remain applicable despite the passing tests.
