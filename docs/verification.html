Reproduce

cmake --build build -j
ctest --test-dir build --output-on-failure
/usr/bin/python3 tests/check_docs.py

# Equivalent bounded groups:
ctest --test-dir build -E '^integration$' --output-on-failure
ctest --test-dir build -R '^integration$' --output-on-failure

# GUI-free sanitizer checks:
cmake -S . -B build-asan -G Ninja -DCMAKE_BUILD_TYPE=Debug \
    -DCPYMACS_GUI=OFF -DCPYMACS_SANITIZERS=ON -DCPYMACS_LTO=OFF \
    -DPython3_EXECUTABLE=/usr/bin/python3
cmake --build build-asan -j
ASAN_OPTIONS=detect_leaks=0 ctest --test-dir build-asan \
    -R 'terminal_|frontends|text_properties' --output-on-failure
ASAN_OPTIONS=detect_leaks=1 ./build-asan/test_term_style

Full-process leak checking is disabled for embedded-Python tests because CPython retains process-global allocations. The isolated palette test uses leak checking. Passing ASan/UBSan checks are evidence about executed paths, not a proof of memory safety.

Historical evidence

The 0.1.0 verification record, original test logs, and original performance results are retained. Those older results include the initial installation-relocation and full backend sanitizer checks. They are not relabeled as new measurements.

Not verified

Windows PuTTY was not installed in the execution environment. The PTY test uses an explicit model of PuTTY's documented colour-acceptance controls; XTerm supplies a separate real-rendering check. These checks do not establish compatibility with every PuTTY release, setting, terminal multiplexer, monitor, font or accessibility filter.

The original limitations remain: no differential GNU Emacs conformance run, controlled editor-to-editor speed comparison, real isort/autopep8 version matrix, physical-desktop Japanese IME test, remote CI execution or GitHub Pages deployment. See Compatibility and Safety.
