Compatibility boundaries

Exactly where familiar Emacs interaction stops being full GNU Emacs behavior.

The requirement of complete basic-command compatibility is not fully met by this release. Common key sequences and ordinary editing cases are implemented and tested, but the differences below remain. This distribution does not claim a full Emacs conformance result.

Implemented subset versus differences

MovementCharacters, lines with goal column, words, line/buffer boundaries, goto.Boundary errors often clamp instead of signaling exactly as Emacs; Unicode syntax tables and mode-specific word semantics differ.

DeletionForward/backward code point, kill line/word/region, horizontal whitespace.backward-delete-char-untabify does not reproduce tab expansion semantics in all cases.
Kill ring60 entries, consecutive append/prepend, yank and yank-pop.No complete interprogram clipboard customization or kill-ring browser.
UndoNative differential edit records, command groups, explicit redo, clean-state tracking.No Emacs undo-of-undo behavior, full undo boundary grouping or alternate undo history tree. Typed key events can undo individually.
SearchLiteral incremental forward/backward search and cancellation.Case-sensitive only; no smart case, regular expressions, full isearch keymap or Unicode case-fold matching.
ReplacementLiteral replace-string and interactive query replace.No regexp captures or Emacs case-preserving replacement.
Numeric argumentsC-u, repeated universal arguments, Meta digits and negative arguments for supported commands.Counts are bounded; command-specific corner cases and zero-prefix transpose are not all implemented.
IndentationLiteral four-space default; Python colon heuristic; optional two-space web profile.Not GNU Emacs TAB semantics, full Python indentation or CC/web-mode indentation engines. The literal-space default is intentional.

ScrollingPage movement and centered recenter.recenter-top-bottom always centers rather than reproducing the full center/top/bottom cycle.
MacrosRecord/replay canonical key events.No full macro editor, counters or complete replay semantics; multi-character IME/bracketed-paste events are not recorded as full macros.

What was compared

The test suite specifies expected results for selected ordinary command sequences. It was executed against cpymacs. GNU Emacs was not installed in the verification environment, so a same-sequence differential run against a particular Emacs release was not performed. The tests are regression checks, not a certificate of complete compatibility.

Supported platform and limits

This implementation targets GNU/Linux. It uses /proc/self/exe, Linux peer credentials and Unix sockets. Windows and macOS builds are not claimed. The GUI needs X11/XWayland. Buffer count is limited to 256, panes to eight, protocol peers to 32. Very large files remain editable as UTF-8 but highlighting and transfer operations have explicit size limits.

Old plugins

simplepypad plugins that receive Tk widgets, curses windows or previous Python editor internals must be ported. Lisp packages cannot be imported. Use the Python API and native command names rather than frontend internals.
