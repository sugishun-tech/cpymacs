Client protocol v1

A local JSON Lines interface for attaching independent terminal, GUI or custom clients to one editing backend.

Transport

--backend and --batch read one JSON object per newline from stdin and write one response per newline to stdout. Standalone frontends use a socketpair and a child backend. --server PATH offers the same protocol over a Unix socket. No TCP listener or HTTP service is provided. Plugin printing is redirected to stderr.

Frame input is limited to 16 MiB. A server accepts up to 32 peers, checks the Linux peer UID, creates its socket with mode 0600 and refuses to overwrite an existing path. Per-peer queued output is limited to 64 MiB. Clients should serialize requests and read complete replies; there are no asynchronous notifications. Idle snapshots are explicit polling.

First exchange

{"id":1,"op":"hello","rows":40,"cols":120}
{"id":2,"op":"insert","text":"hello\nworld"}
{"id":3,"op":"keys","keys":["M-<","C-n","C-a"]}
{"id":4,"op":"get_text","start":0,"end":11,"no_snapshot":true}

A successful response has ok: true, the echoed id when supplied, an optional result, and usually state. Failed validation returns ok: false with an error. Early validation failures can omit the request ID. Clients must handle a missing state on failure rather than assuming a fixed response shape.

{"ok":true,"id":4,"result":"hello\nworld"}

Operations

opFields and result
hello / snapshotOptional rows and cols; return current viewport. Clamped to rows 4..200, columns 12..500.
keykey: canonical token such as C-f, M-x, TAB, RET or a UTF-8 character.
keyskeys: array of at most 10,000 tokens. Sequential execution, not an atomic transaction.
inserttext: literal text or bracketed paste. Buffer control characters are not interpreted as key commands; prompt paste follows the active prompt policy.
commandname, optional string argument, optional integer count. Invoke the same native/Python command dispatch.
openpath: UTF-8 file path.
saveOptional path and force boolean. Defaults to the current file; stale-file checks apply unless forced.
get_textOptional start/end UTF-8 byte offsets, half-open range. Returns a string. At most 2 MiB per request; retrieve larger files in code-point-aligned chunks.
replaceRequired integer start/end and string text. Replace half-open native byte range.
set_texttext: replace the complete current buffer using native prefix/suffix differencing.
pointbyte: zero-based UTF-8 byte boundary.
clickpane index, zero-based physical line and display column; optional extend boolean to extend selection.
commandsReturns native and registered Python command names.
selectionReturns active-region text, at most 2 MiB.
kill_ringReturns the most recent kill text, at most 2 MiB.
yank_externaltext: add external clipboard text to native yank behavior, or paste into an active prompt.
quitOptional force boolean. Without force, request ordinary modified-buffer confirmation; forced quit can discard unsaved work.

All operations may include id, rows, cols and no_snapshot. Native document positions are zero-based UTF-8 byte offsets. NUL is rejected. Literal raw Unicode and JSON Unicode escapes are accepted. Numeric strings are not interchangeable with integer fields for validated operations. The protocol is not a stable general-purpose network API.

State shape

The top level includes protocol, dimensions, message, prompt, input, input_point, pending key prefix, quit/detach flags, theme/font settings, ten RGB colors, kill_generation and a panes array.

Each pane includes its index, buffer id, x/y/width/height cell rectangle, gutter, top physical line, left display column, active flag, buffer name/path/mode, point/mark, byte size, character and line counts, revision, modified/read-only/selection flags, indentation settings, cursor row/column, modeline and visible lines. A row has text, its physical line, source byte offset and spans.

Spans are triples [start, end, style], where offsets are UTF-8 bytes in the display row string, not the raw file. Tabs have already expanded to spaces and unsafe controls are rendered with caret notation. Style IDs match the theme slots documented under Python API. Row -1 denotes filler below the document. Do not send display-string offsets back as document positions.

Minimal standard-library client

import json
import subprocess

with subprocess.Popen(
    ["./build/cpymacs", "--batch", "--no-user-config"],
    stdin=subprocess.PIPE, stdout=subprocess.PIPE,
    text=True, encoding="utf-8", bufsize=1,
) as process:
    def request(payload):
        process.stdin.write(json.dumps(payload, ensure_ascii=False) + "\n")
        process.stdin.flush()
        line = process.stdout.readline()
        if not line:
            raise RuntimeError("Backend closed the connection")
        reply = json.loads(line)
        if not reply.get("ok"):
            raise RuntimeError(reply.get("error", "Backend error"))
        return reply

    request({"op": "insert", "text": "hello", "no_snapshot": True})
    print(request({"op": "get_text", "no_snapshot": True})["result"])
    request({"op": "quit", "force": True, "no_snapshot": True})

Security and shared state

A connected same-user client can edit files and invoke trusted configured commands. That is powerful access, not a sandbox. There is no arbitrary Python-eval protocol operation, but installed plugins may themselves execute external programs. Use a private socket directory; do not bridge the protocol onto a public network.

All frontends share one point, minibuffer, configuration and layout. Last-received commands act on current backend state. The API has no expected-revision compare-and-swap for normal editing and no conflict-free merge. Rendering dimensions from attached clients can also affect shared viewport behavior.
