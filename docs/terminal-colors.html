Terminal colours and PuTTY

A C-only, high-contrast terminal renderer that does not borrow your default or ANSI-16 palette.

Use the fix

Rebuild 0.1.1 and launch normally. No Python configuration change is required. This rendering policy applies to every terminal theme, including the bundled cyberpunk profile. The X11 GUI and the backend's theme values are unchanged.

./build/cpymacs --nox --config examples/dotemacs.py example.py

What changed

0.1.0 sent only 24-bit foreground and background controls. Version 0.1.1's automatic policy sends a 256-colour pair first and an RGB pair second. A terminal that accepts only one extension retains that pair. Indexed colours use slots 16 through 255, never the configurable basic 16-colour slots. No OSC palette changes, terminal configuration writes, bold-colour tricks, or capability-query round trips are used.

Every painted character and padding cell has an explicit foreground/background pair. Comments, line numbers, mode lines and selected text are repaired to at least 7:1 computed sRGB contrast. The indexed conversion also enforces 7:1, rather than simply rounding the RGB values. Custom themes with unusable mid-grey backgrounds are adjusted before text colours are chosen. These are colour-value guarantees, not guarantees about monitor calibration, font rendering or colour vision.

The terminal uses its own pale-yellow block cursor by default, so an invisible native cursor colour cannot hide the insertion point. Selection adds an underline and mode lines use reverse video. These distinctions remain when colour controls are ignored, provided the terminal's own default foreground and background are distinguishable. Row caching repaints the old and new cursor locations, including split panes and the minibuffer.

Options

OptionBehavior
--tui-colors=autoDefault. For recognized modern TERM names (including xterm, putty, screen and tmux) or a truecolor COLORTERM, send indexed fallback followed by RGB. Unknown, dumb and Linux-console terminal names use monochrome conservatively.
--tui-colors=256Only indexed slots 16–255. Useful when an intermediary incorrectly translates RGB controls.
--tui-colors=truecolorOnly RGB. Requires working 24-bit colour handling throughout the terminal path.
--tui-colors=monoNo colour controls. Use the terminal's own default colours with reverse video and underlining.
--tui-cursor=blockDefault. Draw the block in the editor and hide the native cursor while editing.
--tui-cursor=terminalUse the terminal's native cursor instead. Its colour and shape are the terminal's responsibility.

Both --option=value and --option value forms work. An explicit terminal option implies --nox, even with DISPLAY set. The environment variables CPYMACS_TUI_COLORS and CPYMACS_TUI_CURSOR provide defaults; command-line options take priority. An environment variable alone does not force terminal mode.

./build/cpymacs --nox --tui-colors=256 example.py
./build/cpymacs --nox --tui-colors=mono example.py
export CPYMACS_TUI_COLORS=256
./build/cpymacs --nox --connect "$XDG_RUNTIME_DIR/cpymacs.sock"

These settings belong to each frontend. They can be used with --connect without reconfiguring the shared backend or the GUI. They are rejected with --batch and --server. Invalid values fail before starting a backend. auto is a conservative policy based on environment hints, not a claim to detect PuTTY's live settings.

Limits: colour customization versus refusing colour controls

The PuTTY manual, section 4.13, documents separate switches for accepting ANSI colours, 256 colours and 24-bit colours. It also documents configurable default, basic and cursor colours. Palette customization and disabling a control extension are different operations.

With at least one supported extended colour path enabled, the editor's colours do not depend on the default or basic 16-colour settings. If both extended paths are disabled, only the terminal defaults and non-colour attributes remain. If all colour controls are refused and those defaults are identical, no remote application can create a visible foreground/background contrast. Monochrome mode cannot override that refusal. Terminal-native mouse selection, scrollbars, window borders and operating-system contrast filters are also outside this renderer.

An SSH intermediary or terminal multiplexer can filter or reinterpret controls. Force 256 when that path supports indexed colours but mishandles RGB. Version 0.1.1 does not rewrite palettes to work around this: doing so could alter your shell and other applications.

Verification

The native test checks 257 palettes, including the bundled theme and pathological custom themes. Every RGB and indexed text/background pair passed the 7:1 threshold; the bundled cyberpunk minimum was 7.0232:1. Eleven PTY tests exercise independent colour-extension rejection, hostile default and ANSI palettes, cursor repainting, UTF-8 wide characters, splits, resize, editing, monochrome and existing-server attachment. A real XTerm render comparison also passed; see the pixel comparison record and full test report.

Windows PuTTY itself was not available for execution. The PuTTY switch combinations are modeled from its documented behavior; neither the model nor XTerm testing is a substitute for a run on that exact client.
